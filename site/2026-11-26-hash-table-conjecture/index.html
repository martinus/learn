Did a student break a 40-year-old rule about hash tables?

In 1985 the computer scientist Andrew Yao conjectured a limit for a classic kind of hash table. When only one slot in x is still free, the next insertion must look at about x slots, so a table that is 99% full needs about 100 probes. A paper by Martín Farach-Colton, Andrew Krapivin and William Kuszmaul, published in 2024, describes a table that needs about (logx)2 probes, and proves that no table of this kind can do better. Krapivin found the table as an undergraduate. This page explains the rule, the two new tables, what they cost in real numbers, and what changes for the hash maps in programs.

Status: proven and reviewed, not used in production The proof passed the review of FOCS 2024. This page found no published objection to it as of 26 November 2026. The same authors extended the result in June and in November 2026. No general-purpose hash map library uses the new tables. Experimental libraries implement and measure them.

The rule

A table that puts each key into the first free slot of its probe sequence cannot beat a random probe order in the worst case. A random order needs about x probes when one slot in x is free. Yao conjectured this in 1985.

The result

Funnel hashing follows the same placement rule and needs about (logx)2 probes. Elastic hashing drops the rule and finds an average key in a constant number of probes, however full the table is. Both come with proofs that they are optimal.

The cost

The bounds hide large constants. In a simulation on this page, funnel hashing as the proof specifies it beats a random probe order only when the table is more than about 99.7% full. Production hash maps grow long before that: the map of abseil at 87.5%.
01

What Yao proved and what he guessed

The setting is open addressing with three restrictions. Keys are only inserted and never deleted. The array has a fixed size of n slots. And there is no reordering: a key stays in the slot where its insertion put it. The position of a key in its own probe sequence is its probe complexity. A lookup of this key reads that many slots.

A table is greedy if an insertion walks along the probe sequence and takes the first free slot. Linear probing, quadratic probing and double hashing are greedy. The reference point of the theory is uniform probing: the probe sequence of each key is a random permutation of all slots.

Let the table be so full that one slot in x is free: x=8 at 87.5%, and x=1,000 at 99.9%. The papers write δ (delta) for this free share 1/x. With uniform probing, each probe hits a free slot with the probability 1/x. Two costs follow, both counted in probes:

last insertion≈x,average key≈lnx

The first is the worst-case expected cost: the expected number of probes for the most expensive single key, which is the last one inserted. The second is the amortized expected cost: the average over all keys in the table. It is the expected cost of a lookup of a random key that is present. Both formulas are textbook results for uniform probing.

In 1972 Jeffrey Ullman conjectured that no greedy table has a lower average than this, apart from a constant factor. Yao proved it in 1985, in a paper with the title “Uniform hashing is optimal”. This theorem stands. Yao also conjectured the same for the worst case: every greedy table needs about x probes for its last insertion. This conjecture is the rule of the title. It was open for 39 years.

02

Funnel hashing: greedy and faster

Funnel hashing cuts the array into levels. The first level holds about a quarter of all slots, and each further level has 3/4 of the size of the level before it. Each level consists of buckets of β (beta) adjacent slots. A key hashes to one bucket in each level. The insertion scans the key’s bucket in level 1 and takes the first free slot. If the bucket is full, it continues with the key’s bucket in level 2, and so on.

// C++11 or later. Key 0 is a free slot.
// level[i]: buckets of beta slots each.
// Level i+1 has 3/4 the size of level i.
bool insert(Key k) {
  size_t n = level.size();
  for (size_t i = 0; i < n; ++i) {
    auto& a = level[i];
    size_t nb = a.size() / beta;
    size_t b = hash(k, i) % nb;
    for (size_t s = 0; s < beta; ++s) {
      Key& slot = a[b * beta + s];
      if (slot == 0) { // first free:
        slot = k;      // take it
        return true;
      }
    }                  // bucket full:
  }                    // next level
  reserve.push_back(k); // almost never
  return false;
}

The probe sequence of a key is the chain of its buckets, and the insertion takes the first free slot in it. So the table is greedy in Yao’s sense. A lookup follows the same chain. The proof fixes both parameters from x:

levels=4log2x+10,β=2log2x

For x=8 that is 22 levels with buckets of 6 slots. An insertion reads at most 22 × 6 = 132 slots in the levels, whatever the state of the table is. In general the limit is the product of the two formulas. It grows with the square of a logarithm, and Yao’s rule demands x.

The proof needs no single attempt to succeed. It only shows that each level fills up: once a level has received twice as many attempts as it has slots, fewer than 1 in 64x of its slots are still free, with a probability close to 1. So the levels fill from the top, and the free slots that the table must keep collect in the small levels at the bottom. A key that fails in every level goes to a small reserve array. The paper proves that fewer than n/(8x) keys reach it, again with a probability close to 1. In the simulations of this page, no key did.

03

Elastic hashing: reading ahead, stepping back

Yao’s theorem about the average, lnx, holds for greedy tables. The second table of the paper leaves this class but still never moves a key. Elastic hashing cuts the array into parts A1, A2, and so on, each half as large as the part before it. Inside a part, a key probes random slots. The insertions run in batches. Batch i fills part Ai from 75% until only 1 slot in 2x is free, and at the same time part Ai+1 from empty to 75%.

An insertion in batch i first tries up to f of its slots in the fuller part Ai. If one of them is free, it takes it. If none is free, it takes its first free slot in the emptier part Ai+1. There it succeeds after a few probes, because that part is at most 75% full. The limit f grows while Ai fills. With ε (epsilon) for the share of Ai that is free at this moment, and a constant c:

f=c·min((log2(1/ε))2,log2x)

So an insertion often reads many slots in a part that is nearly full and then steps back to an early slot of the next part. The paper names the table after this elastic movement. The table is not greedy, because the insertion gives up on Ai although later probes there may be free.

The gain comes from who pays for the search. To fill all but one slot in x with random probes, the insertions together need about nlnx probes. This is the coupon collector effect. In a greedy table, each of these probes also lengthens a later lookup, because the key ends where the search ended. In elastic hashing most of them are failed probes into the nearly full part. The insertion pays for them, at most about clog2x each, and the lookup does not.

A lookup does not know the part of its key, so it follows one fixed order that mixes the probes of all parts. In the order of the paper, probe j of part Ai comes at a position of about i·j2. A key of batch i then costs a number of probes in proportion to i. Each batch has about half as many keys as the batch before, so the average over all keys is a constant, whatever x is.

04

What is proven now

The paper pairs each table with a lower bound, so the picture for tables without reordering is complete. All entries hold up to a constant factor.

Cost in probesUniform probingBest greedy tableBest table of any kind
Average keylogxlogx (Yao, 1985)constant (elastic hashing)
Most expensive keyx(logx)2 (funnel hashing)logx (elastic hashing)

“Average key” is the amortized and “most expensive key” the worst-case expected cost of section 01. Source: Theorems 1, 2, 4 and 5 of the paper. The bound below is Theorem 7.

The lower bound for greedy tables builds on Yao’s theorem. In a greedy table, the expected cost of an insertion never falls while the table fills. The average is at least of the order logx. So there is a moment, with one slot in 2i free, at which an insertion costs about i·logx probes. The last insertion pays at least as much, only to reach the slots that were free at that moment. These slots form a smaller table, and the same argument applies to it. The costs add up to a sum of the form 1+2+…+log2x, which grows like (logx)2.

One more bound covers the longest lookup in the whole table and not an expectation. With a probability above 1/2, some key needs about (logx)2+loglogn probes in every table without reordering, greedy or not. Funnel hashing reaches this bound.

What the bounds cost in numbers

The bounds say how the cost grows. They do not say how large it is. The paper contains no measurement, so this page simulates both tables as the paper specifies them. Funnel hashing runs with the constants of its proof. For elastic hashing the proof names no value of c, and this page uses 2. All numbers in this section are results of this page.

With these constants, funnel hashing loses to uniform probing until the table is between 99.6% and 99.8% full. At 87.5% its last insertions cost 56 probes where uniform probing needs 8, and its average key costs 17.4 probes against 2.4. The constants are no tuning. They come from a proof that is written to be short. An independent preprint of September 2026, MultiTable, describes a similar cascade of buckets that is sized for real hardware. Its author reports 5 levels for 100,000 keys at 90% fullness, where the formulas of the proof give 24.

Elastic hashing shows the same pattern in the figure of section 03. At 99.9% an average key costs 22.7 probes, and uniform probing needs 6.9. Uniform probing reaches 22.7 only at x≈e22.7, a table with one free slot in about 7 billion. So for every table that fits into memory, the constant is larger than the logarithm that it replaces. This is an inference of this page. It depends on the choice c=2 and on the probe order of the paper.

06

Who did what

Quanta Magazine reported the story in February 2025. According to this report, Krapivin was an undergraduate at Rutgers University when he met the paper “Tiny Pointers” in 2021. Two years later he worked through it and tried to make its pointers smaller. For that he needed a new hash table, and he built one without knowing Yao’s conjecture. Farach-Colton, his former professor, was sceptical at first. Kuszmaul saw that the table refutes the conjecture.

So the answer to the title is yes, with two additions. The published result, with its proofs and lower bounds, is the joint work of the three authors. And the paper itself says that the level structure of funnel hashing appeared before, for other purposes: in multilevel adaptive hashing (1990) and in filter hashing (2005). New is the proof of what this structure does to Yao’s conjecture.

  1. 1972Ullman conjectures that no greedy table has a lower average cost than uniform probing.
  2. 1985Yao proves Ullman’s conjecture and adds his own about the worst case.
  3. Oct 2024The paper “Optimal Bounds for Open Addressing Without Reordering” appears at FOCS 2024. A public version follows on 4 January 2025.
  4. Jun 2026The same three authors show at STOC 2026 that a constant average is possible with greedy insertion too, if the lookup follows another probe order than the insertion.
  5. 3 Nov 2026A new preprint of the three authors removes the remaining costs. Without reordering, insertions in constant expected time go together with a constant average lookup. With reordering, insertions and all lookups take constant expected time at every fullness, also in a full table.
07

What changes for a real hash map

For the hash maps in today’s programs, nothing changes. There are four reasons.

  • Real maps stay out of the region where the result applies. The SwissTable of abseil grows at 7/8, and unordered_dense 5 at 0.8. At 7/8, the worst case of uniform probing is 8 probes. Maps of this family also compare 16 slots with one instruction. A lookup in a fresh table of unordered_dense 5 reads between 1.03 and 1.09 groups of slots. These numbers come from a survey of nine C++ hash map libraries by the publisher of this site.
  • The model counts slots, and hardware counts cache misses. In funnel hashing, each further level is a jump to another place in memory. This is an inference of this page.
  • The proofs need a fixed size, a known fullness and no deletions. For tables with deletions that never move a key, the paper cites a proof that the average cost must grow like a power of x.
  • Real maps may move keys. Robin hood hashing does. With reordering, a constant average in a full table has been known since a method of Richard Brent from 1973.

One project has measured the new tables. The Rust library opthash implements both with the placement rules of the paper and adds what a usable map needs, such as deletion and growth. It calls itself experimental. Its benchmark of 30 October 2026 compares them with a table that copies the layout of hashbrown, the SwissTable of Rust, without its limit of 7/8. The numbers are nanoseconds per operation on a 64-bit ARM machine, for tables of 1,048,576 slots:

A key that is present is found about ten times more slowly. Insertions win only at 99.9%, which fits the simulation of section 05. The funnel map rejects an absent key faster at every fullness, but this is no property of the table of the paper. In a greedy table a miss costs as much as the next insertion, because both stop at the first free slot. The funnel map of opthash adds a membership filter, and a key that the filter does not know needs no probe at all. These numbers come from one benchmark of one small project, and nobody else has confirmed them. A second project, an implementation of elastic hashing in Zig, reports faster insertions at 99% and slower lookups in large tables. Its author blames cache misses from the jumps between the parts.

The value of the result is in theory: two limits that were assumed for decades do not hold. Alex Conway of Cornell Tech told Quanta that the results may not lead to immediate applications. The MultiTable preprint claims that a cascade of buckets beats hashbrown at equal memory. Its author made these measurements, and nobody has reviewed them.

08

Terms

x (how full the table is)
One slot in x is free, so the table is 1−1/x full: x=8 at 87.5%, x=1,024 at 99.9%. The papers write δ or ε for the free share 1/x.
Probe complexity
The position of a key in its own probe sequence. A lookup of this key reads that many slots. It is fixed when the key is inserted, because the key never moves.
Reordering
Moving a key to another slot after its insertion. Robin hood hashing and cuckoo hashing reorder. The tables of this page do not. Wikipedia: Open addressing
Greedy
An insertion is greedy if it takes the first free slot of the key’s probe sequence. Then an insertion and a lookup that misses read the same slots.
Uniform probing
The idealized greedy table of the theory. The probe sequence of each key is a random permutation of all slots, independent of the other keys.
Worst-case expected cost
The expected number of probes for the single most expensive key. The expectation runs over the random hash function. In a greedy table this key is the last one inserted.
Amortized expected cost
The expected number of probes, averaged over all keys in the table. It is the expected cost of a lookup of a random key that is present. It says nothing about keys that are absent.
Level
One of the sub-arrays of a funnel table. Each level has 3/4 of the size of the level before it. A key tries the levels in order.
Bucket and β (beta)
In funnel hashing, a bucket is a run of β adjacent slots inside a level. A key hashes to one bucket per level. The proof sets β=2log2x.
Batch
In elastic hashing, a run of consecutive insertions that all go into the same two neighbouring parts of the array.
f
The largest number of slots that an insertion of elastic hashing tries in the fuller of its two parts before it turns to the emptier part.
ε (epsilon)
On this page: the share of slots that is free, at one moment, in the fuller of the two parts that an elastic table is filling.
c
A constant of elastic hashing that scales the limit f. The proof only requires that it is large enough. The simulation of this page uses c=2.
Coupon collector
A classic problem of probability: how many random draws does it take to see most or all of n different coupons? To see all but a share 1/x of them takes about nlnx draws. Wikipedia: Coupon collector’s problem
FOCS (Symposium on Foundations of Computer Science)
A yearly conference of the IEEE and one of the two main conferences of theoretical computer science. Papers are reviewed before they are accepted.
STOC (Symposium on Theory of Computing)
A yearly conference of the ACM, the other main conference of theoretical computer science, with the same kind of review.
Preprint
A scientific paper that its authors publish themselves, before a conference or a journal has had it reviewed by independent experts.

How sure is this?

  • Sourced Both tables, their parameters, all bounds and the outline of the proofs come from the paper of Farach-Colton, Krapivin and Kuszmaul. This page read its second public version in full. The history of the conjecture comes from the introduction of that paper. The follow-up of November 2026 comes from the introduction of its preprint. The benchmark numbers come from the pull request of opthash, and the numbers on production maps from the survey that is linked there.Who found what, and when, rests on the report of Quanta Magazine alone. That survey is by the publisher of this site.
  • Inferred Every number in section 05 and in the figures of sections 02 and 03 is a simulation on this page, with the constants of the proofs and one fixed sequence of random numbers. The paper has no measurements. The fullness at which funnel hashing overtakes uniform probing, and the statement that the constant of elastic hashing is larger than lnx for every practical table, follow from these simulations. Two simplifications: a funnel level smaller than one bucket is left out, and lookups in the elastic table skip positions of the probe order that the paper leaves unused.The cost formulas of uniform probing are textbook knowledge of the model that wrote this page. Also inferred: that the conjecture was open for 39 years, and that cache misses limit funnel hashing.
  • Uncertain How the new tables perform as real code. One hobby project measured them on one machine, and a second reports a similar pattern. Nobody has confirmed either. The claims of the MultiTable preprint are measured by its author only.Read as an abstract only: the STOC 2026 paper and “Tiny Pointers”. Not read: Yao’s paper of 1985. Its content is given as the 2024 paper reports it. A better constant c or probe order may lower the cost of elastic hashing. With the best fixed order for the simulated run, its average was 11.9 probes, still above 6.9.
